# Geran — игровая сущность SVOperation

Статус: проектирование игрового вертикального среза. Это вымышленная Minecraft-механика; документ не описывает реальную навигацию или устройство БПЛА.

## Цель

Добавить управляемую игроком игровую сущность «Герань» с отдельной 3D-моделью, предметом запуска, выбором точки назначения в пределах загруженного игрового мира, полётом, отменой и эффектом столкновения.

## Игровой цикл

1. Игрок получает предмет «Пульт БПЛА».
2. В режиме выбора точки игрок отмечает блок/позицию в мире. Интерфейс показывает только игровые координаты и допустимость точки.
3. Игрок подтверждает запуск. Сервер проверяет предмет, дистанцию, мир, загруженность чанка и ограничения режима.
4. Сервер создаёт сущность «Герань» в игровой сцене и синхронизирует её состояние клиентам.
5. Сущность движется по простой игровой интерполяции к отмеченной точке. Это не физическая/авиационная модель и не система реального наведения.
6. До финальной фазы игрок может отменить сценарий; при отмене сущность исчезает без взрыва.
7. При достижении игровой точки или столкновении запускается визуальный эффект, звук и ограниченный игровой взрыв.
8. После завершения сохраняется короткое состояние/событие для HUD, затем сущность удаляется.

## Состояния

- IDLE — пульт готов.
- POINT_SELECTED — точка выбрана, запуск ещё не подтверждён.
- LAUNCHING — короткая игровая анимация старта.
- IN_FLIGHT — сущность летит к игровой точке.
- ABORTED — сценарий отменён.
- IMPACT — столкновение и визуально-звуковой эффект.
- FINISHED — завершение и очистка сущности.

Переходы выполняются на сервере; клиент отображает полученное состояние и не определяет исход столкновения.

## Управление и HUD

- ЛКМ по блоку в режиме выбора — установить игровую точку.
- Подтверждение отдельной кнопкой интерфейса — запуск.
- Отмена — до состояния IMPACT.
- HUD: выбранная игровая точка, статус, условная шкала прогресса, подсказки.
- Не использовать реальные карты, географические координаты, внешние сервисы, автопилот или данные наведения.

## Модель и визуал

Нужна новая самостоятельная модель, не переиспользующая модель винтовки:
- цельный вытянутый корпус с отдельными визуальными узлами для носовой части, крыльев, хвостового оперения, двигателя/пропеллерной зоны и мелких деталей;
- читаемый силуэт с расстояния в Minecraft;
- PBR/диффузные материалы: матовый светлый корпус, тёмные панели, предупреждающие маркировки без реальных серийных номеров;
- корректный pivot и ориентация по направлению движения;
- LOD/упрощённая геометрия для дальнего отображения;
- отдельные анимации старта, полёта и исчезновения;
- масштаб и точка крепления проверяются в игре, а не только в 3D-редакторе.

Модель должна быть оригинальной игровой интерпретацией, а не копией закрытой CAD/военной модели. Любые сторонние ассеты допускаются только после проверки лицензии и происхождения.

## Архитектура кода

- registry/SVEntities — регистрация типа сущности.
- entity/GeranEntity — серверное состояние, игровая траектория, столкновение и очистка.
- item/GeranControllerItem — выбор игровой точки и подтверждение.
- network/GeranMessages — минимальные сообщения клиент ↔ сервер с проверкой дистанции и состояния.
- client/GeranRenderer и модель/текстуры — только клиентская часть.
- registry/SVSounds — запуск, полёт, столкновение.
- assets/svoperation/lang — RU/EN локализация.

Не загружать клиентские классы на dedicated server. Не доверять координатам, присланным клиентом без серверной проверки. Ограничить частоту сообщений, дистанцию выбора и количество активных сущностей на игрока/мир.

## Приёмочные проверки

- чистая сборка Forge 1.21.1 / Java 21;
- загрузка dedicated server без client-only классов;
- регистрация предмета и сущности без ошибок;
- выбор точки, подтверждение, отмена;
- синхронизация состояния в мультиплеере;
- столкновение с блоком и землёй;
- эффект не запускается дважды;
- удаление сущности после завершения;
- проверка модели спереди/сбоку/сверху и при полёте;
- проверка дальности прорисовки и производительности.

## Ограничения первой версии

Первая версия — сценарная игровая сущность с одной точкой назначения. Не добавлять сложные реальные системы наведения, автономного распознавания целей, физику реального полёта или привязку к реальным координатам.
